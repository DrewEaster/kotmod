# Querty Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Querty, a library that generates typed Kotlin from named queries in plain `.sql` files using a live, migrated Postgres schema, plus a blocking JDBC engine and a Kotmod example app that proves it.

**Architecture:** Three library modules: `querty`, a dependency-free runtime of query values, parameters and a row-reading interface; `querty-jdbc`, the blocking engine; and `querty-codegen`, which parses `.sql` files, describes each query against Testcontainers Postgres and emits Kotlin. An unpublished `kotmod-querty-example` module rebuilds the README's Orders/Customers domain on Querty. Its generated code is committed and checked by a Gradle task.

**Tech Stack:** Kotlin 2.4.20, JVM 25, Gradle 9.8 (`kotmod.library` convention), pgjdbc 42.7.13, Testcontainers Postgres 2.0.5 (`postgres:17`), JUnit 5 via `kotlin("test")`.

**Spec:** `docs/superpowers/specs/2026-10-21-querty-design.md`

## Global Constraints

- The `querty` module depends only on the Kotlin stdlib. `querty-jdbc` depends only on `querty` and the JDK's `java.sql`. Generated code imports only `io.querty.*`, app types and stdlib/`java.*` types.
- Package root `io.querty` (codegen: `io.querty.codegen`, JDBC: `io.querty.jdbc`).
- Every module applies `kotmod.library`, not `kotmod.published`. Nothing is published.
- Kotmod's own modules (`kotmod`, `kotmod-sqldelight`, `kotmod-db-scheduler`) do not change and must not depend on Querty.
- A normal `./gradlew build` / `test` needs no Docker. Anything that starts Postgres lives in `integrationTest`.
- Postgres image default `postgres:17`.
- No backwards-compatibility concerns (nothing is released).
- Commands run from the repo root `/Users/dreweaster/projects/kotmod`. For runs longer than a few minutes, prefix with `caffeinate -is`.

## Review Focus

1. **jsonb `?` operators in user SQL.** pgjdbc treats `?` as a placeholder, so rendering for JDBC must escape a literal `?` as `??`. Expected: `SELECT '{"a":1}'::jsonb ? 'a'` runs and returns true (test in Task 1 and Task 2).
2. **Colons that aren't parameters**, such as `::casts`, `':x'` string literals, `"quoted:x"` identifiers, `-- :x` and `/* :x */` comments, `$$ :x $$` / `$tag$ … $tag$` bodies, and `arr[1:2]` slices. Expected: none become parameters (test in Task 4).
3. **Error lines after snippet expansion and directive stripping.** Expected: a Postgres error in a query that uses a snippet reports the `.sql` file and line where the bad text actually is (test in Task 4 for the map, and Task 8 end to end).
4. **One parameter name used in two places with different Postgres types.** An example is `:x` compared with an `int4` and a `text` column. Expected: a generation error naming both types, never a silent pick (test in Task 7).
5. **Stale generated files.** If a `.sql` file is deleted or renamed, the next `generate` must remove its old `.kt` file, and `check` must flag the leftover (test in Task 8).

**Files:**

- Create: the six files under `querty/src/main/kotlin/io/querty/` listed above
- Test: `querty/src/test/kotlin/io/querty/SqlTemplateTest.kt`

**Interfaces:**
- Produces:
  - `@JvmInline value class PgType(val name: String)`. `name` is the pg_type `typname`, e.g. `"text"`, `"int4"`, `"timestamptz"`, and arrays use the leading underscore, e.g. `"_int4"`. It has `val isArray: Boolean`, `val elementType: PgType` (strips `_`), and companion constants `TEXT, VARCHAR, BPCHAR, NAME, INT2, INT4, INT8, BOOL, FLOAT4, FLOAT8, NUMERIC, TIMESTAMPTZ, TIMESTAMP, DATE, UUID, BYTEA, JSON, JSONB`.
  - `data class Param(val name: String, val value: Any?, val type: PgType)`. For array types, `value` is a `List<*>` of base JVM values.
  - `enum class PlaceholderStyle { NUMBERED, POSITIONAL }`
  - `class SqlTemplate(val parts: List<String>, val refs: List<Int>)`.
    - Requires `parts.size == refs.size + 1`. `refs[k]` is the 0-based index into the statement's `params` of the reference between `parts[k]` and `parts[k+1]`.
    - `fun render(style: PlaceholderStyle): String`. `NUMBERED` writes `$${ref+1}`. `POSITIONAL` writes `?` and replaces every literal `?` inside `parts` with `??`.
    - `fun bindOrder(style: PlaceholderStyle, params: List<Param>): List<Param>`. `NUMBERED` returns `params`; `POSITIONAL` returns `refs.map { params[it] }`.
  - `interface RowReader`, 0-based column index, each returning null for SQL NULL:
    - `string(i): String?`, `int(i): Int?`, `long(i): Long?`, `boolean(i): Boolean?`, `float(i): Float?`, `double(i): Double?`
    - `bigDecimal(i): java.math.BigDecimal?`, `instant(i): kotlin.time.Instant?`, `localDateTime(i): java.time.LocalDateTime?`, `localDate(i): java.time.LocalDate?`, `uuid(i): java.util.UUID?`, `bytes(i): ByteArray?`
    - `list(i, elementType: PgType): List<Any?>?`
  - `fun <T : Any> notNull(value: T?, column: String): T`. It throws `IllegalStateException("Column '$column' was null but is declared non-null")`.
  - `sealed class Statement(val template: SqlTemplate, val params: List<Param>)`. It has `val sql: String` (rendered `NUMBERED`) and `override fun toString()` returning `sql`.
  - `class OneQuery<R>(template, params, val mapper: (RowReader) -> R) : Statement`, and `OptionalQuery<R>` and `ManyQuery<R>` with the same constructor. `class AffectedQuery(template, params) : Statement`.
  - `class UnexpectedRowCountException(val expected: String, val actual: Int, sql: String) : RuntimeException`. The message is `"Expected $expected row(s) but got $actual: $sql"`, where `expected` is `"exactly one"` or `"at most one"`.

### Task 2: `querty-jdbc` engine

**Files:**
- Modify: `settings.gradle.kts` (add `"querty-jdbc"`)
- Create: `querty-jdbc/build.gradle.kts`. It has `api(project(":querty"))`, plus `integrationTestImplementation` on `org.testcontainers:testcontainers-postgresql:2.0.5` and `org.postgresql:postgresql:42.7.13`. Do **not** depend on Kotmod's test fixtures.
- Create: `JdbcBinding.kt`, `JdbcRowReader.kt`, `Execute.kt` in `querty-jdbc/src/main/kotlin/io/querty/jdbc/`
- Test: `querty-jdbc/src/integrationTest/kotlin/io/querty/jdbc/JdbcExecuteIntegrationTest.kt`

**Interfaces:**
- Consumes: Task 1 types.
- Produces:
  - `fun <R> OneQuery<R>.execute(connection: Connection): R`
  - `fun <R> OptionalQuery<R>.execute(connection: Connection): R?`
  - `fun <R> ManyQuery<R>.execute(connection: Connection): List<R>`
  - `fun AffectedQuery.execute(connection: Connection): Long` (uses `executeLargeUpdate`)
  - `internal fun PreparedStatement.bind(params: List<Param>)`
  - `internal class JdbcRowReader(private val rs: ResultSet) : RowReader`
  - The engine never calls `commit`, `rollback`, `close` or `setAutoCommit` on the connection.

Binding rules by `Param.type`:
- `timestamptz`: `OffsetDateTime.ofInstant(value.toJavaInstant(), ZoneOffset.UTC)`
- `timestamp`, `date`, `uuid`: `setObject`
- `json`, `jsonb`: `setObject(i, string, Types.OTHER)`
- array types: `connection.createArrayOf(elementType.name, list.toTypedArray())`, with `timestamptz` elements converted as above
- `null`: `setNull(i, Types.OTHER)` for json, jsonb, uuid and arrays, otherwise `setObject(i, null)`
- everything else: `setObject(i, value)`

Reading `timestamptz` uses `getObject(i+1, OffsetDateTime::class.java)` converted to `kotlin.time.Instant`. Primitives use `getObject(i+1, Long::class.javaObjectType)` and so on, so a SQL NULL reads as null without `wasNull()`.

**Interfaces:**
- Produces:
  - `data class QuertyError(val file: String, val line: Int, val message: String)` with `toString() = "$file:$line: $message"`
  - `class QuertyException(val errors: List<QuertyError>) : RuntimeException(errors.joinToString("\n"))`
  - `enum class Shape { ONE, OPTIONAL, MANY, AFFECTED }`, parsed from `:one`, `:optional`, `:many`, `:affected`
  - `data class TypeDecl(val kotlinType: String, val isEnum: Boolean)`
  - `data class SourceText(val file: String, val firstLine: Int, val text: String)`. This is the body as it appears in the file, with directive lines removed and the line numbers preserved, as explained under Step 3.
  - `data class QueryDef(val name: String, val shape: Shape, val doc: String?, val types: Map<String, TypeDecl>, val imports: List<String>, val notNull: Set<String>, val nullable: Set<String>, val body: SourceText)`
  - `data class SnippetDef(val name: String, val body: SourceText)`
  - `data class ParsedFile(val path: String, val fileImports: List<String>, val queries: List<QueryDef>, val snippets: List<SnippetDef>)`
  - `object SqlFileParser { fun parse(path: String, text: String): ParsedFile }`. It throws `QuertyException` holding all errors found in the file.

Directive grammar: lines that, after trimming, start with `-- :`.
- `-- :name <kebab> <shape>` starts a query; `-- :snippet <kebab>` starts a snippet.
- After `:name` and before the body: `-- :doc <text>` (repeated lines join with `\n`), `-- :type <name> <KotlinType> [enum]`, `-- :import <fqcn>`, `-- :not-null <column>`, `-- :nullable <param>`.
- `-- :import` lines before the first `:name`/`:snippet` are file-level imports.
- A name matches `[a-z][a-z0-9-]*`. Any other `-- :` directive is an error.

### Task 4: SQL rewriter: lexing, snippets, parameters, source map

**Files:**
- Create: `querty-codegen/src/main/kotlin/io/querty/codegen/SqlRewriter.kt`
- Test: `querty-codegen/src/test/kotlin/io/querty/codegen/SqlRewriterTest.kt`

**Interfaces:**
- Consumes: `QueryDef`, `SnippetDef`, `SourceText`, `QuertyError`/`QuertyException`.
- Produces:
  - `data class RewrittenQuery(val parts: List<String>, val refs: List<Int>, val paramNames: List<String>, val sourceMap: SourceMap)`
    - `paramNames` are in first-appearance order, and `refs` index into them, matching `SqlTemplate`'s contract.
    - It has `fun numberedSql(): String` and `fun positionalSql(): String`, which use the same rules as `SqlTemplate.render`.
  - `class SourceMap`, with `fun locate(numberedSqlOffset: Int): Pair<String, Int>` returning the file and 1-based line, which may be inside a snippet's file.
  - `fun RewrittenQuery.locateServerOffset(offset: Int): Pair<String, Int>` maps an offset into the SQL that pgjdbc actually sends to the server back to a file and line. pgjdbc sends `positionalSql()` with the k-th `?` rewritten to `$k` (counting every occurrence, so repeats get new numbers) and `??` collapsed to `?`. This is the offset Postgres error positions refer to, and it differs from `numberedSql()` whenever a parameter repeats or has `$10`+ numbers.
  - `object SqlRewriter { fun rewrite(query: QueryDef, snippets: Map<String, SnippetDef>): RewrittenQuery }`. It throws `QuertyException`.
- Lexing rules: outside single-quoted strings (with `''` escapes and `E'…'` backslash escapes), double-quoted identifiers, `--` line comments, `/* */` block comments (nested) and dollar-quoted strings (`$$` / `$tag$`):
  - `:name` with `name` matching `[a-z_][a-z0-9_]*` is a parameter when not preceded by `:`.
  - `{{snippet-name}}` is a snippet reference.
- Snippets expand recursively. A cycle is an error naming the chain; an unknown snippet is an error at the reference's line. Parameters inside a snippet body belong to the including query.

- [ ] **Step 1: Write the failing tests.**
  - `named parameters become numbered and a repeat reuses its number`: `WHERE a = :x AND b = :y OR c = :x` gives `numberedSql()` ending in `a = $1 AND b = $2 OR c = $1`, with `paramNames == ["x", "y"]`.
  - `casts are not parameters`: `:x::text` gives `$1::text`, with `paramNames == ["x"]`.
  - `colons in strings, quoted identifiers, comments, dollar quotes and slices are untouched`. Each of these is unchanged and has no params: `':x'`, `E'\':x'`, `"a:x"`, `-- :x`, `/* :x /* :y */ */`, `$$ :x $$`, `$f$ :x $f$`, `arr[1:2]`.
  - `snippet is expanded and its parameters join the query`.
  - `unknown snippet reports the referencing line`.
  - `snippet cycle is an error`: the message contains `a -> b -> a`.
  - `server offsets map back past placeholders`: for `SELECT :a, :a, nope` with `nope` on line 2 of the file, the offset of `nope` in `SELECT $1, $2,\nnope` maps to line 2.
  - `source map points into the snippet's file and line`: a snippet defined at line 3 of `shared.sql` and used at line 10 of `orders.sql`. The offset of the snippet's second line maps to `"shared.sql" to 4`, and the offset after the reference maps back to `orders.sql` line 10 or later.

### Task 5: Naming, type mapping and outer-join detection

**Files:**
- Create: `Naming.kt`, `TypeMapping.kt`, `OuterJoins.kt` in `querty-codegen/src/main/kotlin/io/querty/codegen/`
- Test: `NamingTest.kt`, `TypeMappingTest.kt`, `OuterJoinsTest.kt`

**Interfaces:**
- Produces:
  - `object Naming`, with `fun objectName(kebab: String): String` (`find-order` gives `FindOrder`), `fun propertyName(snake: String): String` (`customer_id` gives `customerId`, `ssl_valid_from` gives `sslValidFrom`), and `fun fileName(sqlPath: String): String` (`orders.sql` gives `OrdersQueries.kt`, `order_status.sql` gives `OrderStatusQueries.kt`). A Kotlin hard keyword gets backticks.
  - `data class BaseType(val kotlinType: String, val readCall: String)`. `readCall` is the `RowReader` method name.
  - `object TypeMapping`, with `fun base(type: PgType): BaseType?`, following the spec table:
    - `text`/`varchar`/`bpchar`/`name`: String/`string`
    - `int2`/`int4`: Int/`int`
    - `int8`: Long/`long`
    - `bool`: Boolean/`boolean`
    - `float4`: Float/`float`
    - `float8`: Double/`double`
    - `numeric`: `java.math.BigDecimal`/`bigDecimal`
    - `timestamptz`: `kotlin.time.Instant`/`instant`
    - `timestamp`: `java.time.LocalDateTime`/`localDateTime`
    - `date`: `java.time.LocalDate`/`localDate`
    - `uuid`: `java.util.UUID`/`uuid`
    - `bytea`: ByteArray/`bytes`
    - `json`/`jsonb`: String/`string`
    - arrays: the element mapping with `readCall = "list"`. The `kotlinType` is the element type; callers wrap it in `List<…>`.
    - anything else gives `null`.
  - `object OuterJoins`, with `fun nullableTables(sql: String): NullableTables`:
    - `sealed interface NullableTables`
    - `data class Known(val tables: Set<String>) : NullableTables` holds lower-cased *table* names, not aliases, that sit on the nullable side of an outer join anywhere in the top-level `FROM`.
    - `data object Unknown : NullableTables`
    - Rules: `LEFT JOIN t` makes `t` nullable. `RIGHT JOIN t` makes every table before it nullable. `FULL JOIN t` does both. Schema-qualified names use the table part.
    - The result is `Unknown` when there's an outer join and the FROM clause contains a parenthesised join, a subquery or a `LATERAL`. No outer join gives `Known(emptySet())`.
    - Scanning skips strings and comments using the same lexing rules as Task 4. Factor a shared `SqlLexer` out of `SqlRewriter` if that's simpler.

    - It catches `PSQLException`, using `serverErrorMessage.position` minus 1 and `serverErrorMessage.message`.

### Task 7: Query model and Kotlin emission

**Files:**
- Create: `QueryModel.kt`, `KotlinEmitter.kt`
- Test: `QueryModelBuilderTest.kt`, `KotlinEmitterTest.kt` (unit tests that feed a hand-built `Description`, no Docker)

**Interfaces:**
- Consumes: `QueryDef`, `RewrittenQuery`, `Description`, `TypeMapping`, `Naming`, `OuterJoins`.
- Produces:
  - `data class ParamModel(val sqlName: String, val kotlinName: String, val type: PgType, val baseType: BaseType, val decl: TypeDecl?, val nullable: Boolean)`
  - `data class ColumnModel(val label: String, val kotlinName: String, val type: PgType, val baseType: BaseType, val decl: TypeDecl?, val nullable: Boolean)`
  - `data class QueryModel(val def: QueryDef, val objectName: String, val rewritten: RewrittenQuery, val params: List<ParamModel>, val columns: List<ColumnModel>, val imports: List<String>)`
  - `object QueryModelBuilder`, with `fun build(def: QueryDef, rewritten: RewrittenQuery, description: Description, fileImports: List<String>): QueryModel`. It throws `QuertyException`; each error carries the file and line of the `-- :name` line, or the directive's line.
  - `object KotlinEmitter`, with `fun emit(packageName: String, models: List<QueryModel>): String`.

Validation rules for `QueryModelBuilder`. Each is an error:
- **Param types.** Each name's type comes from its positional types. If the positions disagree, the error is `Parameter 'x' is used as int4 and text; cast one use so they agree` (Review Focus 4).
- **Unsupported types.** If a param or column type isn't in `TypeMapping`, the error is `Column 'tx' has unsupported type xid8; cast it in SQL (e.g. tx::text)`.
- **Shape and rows.** `:one`, `:optional` or `:many` with no result columns is an error, and so is `:affected` with result columns.
- **Duplicate labels.** A duplicate column label is an error: `Column label 'id' appears twice; alias one of them`.
- **Unknown names in directives.** A `-- :type` naming neither a param nor a column is an error, and so is a `-- :not-null` naming no column or a `-- :nullable` naming no param.
- **Enum types.** `enum` on a non-`text`/`varchar` type is an error.

Nullability:
- A column is non-null when `baseTable != null`, `baseNotNull` is true, and `OuterJoins.nullableTables(numberedSql)` is `Known` without `baseTable` in it. It is also non-null when it's listed in `notNull`.
- A param is nullable only when it's listed in `nullable`.

Emitted shape, with the exact formatting left to the builder; the tests assert fragments:

```kotlin
// Generated by Querty from orders.sql. Do not edit.
package io.kotmod.querty.example

import io.querty.*
import <imports>

/** <doc> */
object FindOrder {
    data class Row(val id: OrderId, val reason: String?, val placedAt: kotlin.time.Instant)

    private val TEMPLATE = SqlTemplate(listOf("SELECT … WHERE o.id = ", ""), listOf(0))

    operator fun invoke(id: OrderId): OptionalQuery<Row> =
        OptionalQuery(TEMPLATE, listOf(Param("id", id.value, PgType("text")))) { r ->
            Row(
                id = OrderId(notNull(r.string(0), "id")),
                reason = r.string(1),
                placedAt = notNull(r.instant(2), "placed_at"),
            )
        }
}
```

- **Value-class columns:** `Type(read)`; in params, `.value`. With `nullable`, use `?.let { Type(it) }` and `?.value`.
- **Enum columns:** `Type.valueOf(read)`; in params, `.name`.
- **List columns:** `(r.list(i, PgType("int4")) as List<Int?>?)`, with a `@Suppress("UNCHECKED_CAST")` on the object. A list param with a decl maps elements: `ids.map { it.value }`.
- **Template strings:** emitted as Kotlin string literals with `\`, `"`, `$` and newlines escaped. The rewritten SQL keeps the user's line breaks.
- **Parameter order:** follows `paramNames`, first appearance in the SQL.

  - Emitter fragments:
    - A value-class param and column, nullable and not.
    - An enum param and column.
    - A list param with `= ANY`.
    - Each shape gives the matching query type, with `AffectedQuery` emitting no `Row`.
    - `$` and `"` in SQL are escaped.
    - `:doc` becomes KDoc.
    - Imports are deduplicated and sorted.

**Interfaces:**
- Produces:
  - `data class GeneratorConfig(val sqlDir: Path, val schema: List<Path>, val outDir: Path, val image: String = "postgres:17")`
  - `object Generator`:
    - `fun generate(config: GeneratorConfig)`. It throws `QuertyException` with every error from every file and writes nothing when there are any.
    - `fun check(config: GeneratorConfig): List<String>`. It returns differences such as `"stale: shop/OrdersQueries.kt"`, `"missing: …"` and `"extra: …"`; an empty list means up to date.
  - `fun main(args: Array<String>)` in `Main.kt`, with the main class `io.querty.codegen.MainKt`.
    - Arguments: `--sql-dir <dir> --schema <path> [--schema <path>…] --out <dir> [--image <image>] (generate|check)`.
    - On `QuertyException` or a non-empty check, it prints each line to stderr and calls `exitProcess(1)`.

Pipeline:
1. Parse every `**/*.sql` under `sqlDir`. The package comes from the directory relative to `sqlDir`, with `/` replaced by `.`.
2. Snippets come from all files and their names must be globally unique.
3. Rewrite every query.
4. Start one `SchemaDatabase`.
5. Describe each query's `positionalSql()`. A `Failed` result maps its position through `RewrittenQuery.locateServerOffset`, giving a `QuertyError(file, line, "Postgres: $message")`. Without a position, use the `:name` line.
6. Build the models.
7. Emit one file per `.sql` file that has queries.
8. **Write.** Write into a temp dir, then replace `outDir`'s generated `*.kt` files (any file starting with the `// Generated by Querty` header) with the new set, deleting ones that no longer have a source (Review Focus 5). Non-Querty files in `outDir` are never touched.

`check` generates into a temp dir and compares it with `outDir` file by file.
